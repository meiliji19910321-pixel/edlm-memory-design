# 融合记忆框架设计

## Context

当前记忆系统：纯手动 md 文件 + frontmatter，无向量检索，无自动采集，无自进化。
目标：打造一个记得清、记得牢、永久自进化、体量小、无外部 API 依赖的超级第二记忆层。

三个参考框架：
- **claude-mem**：生命周期钩子 + 渐进式注入 + 3层检索节省 token
- **MemPalace**：结构化 palace 概念 + 高召回率 + 知识图谱时间窗
- **palaia**：MCP 全工具化 + sqlite-vec 原生集成 + HOT/WARM/COLD 分层

---

## Solution

### 存储架构

```
D:\CLAUDE.MD\mem\
├── .db/
│   ├── memory.db          # SQLite + FTS5 + sqlite-vec（向量）
│   └── wal-journal/       # WAL 模式，断电安全
├── conversations/         # 原始对话暂存（60天后自动清除）
│   └── YYYY-MM-DD-{id}.jsonl
├── memories/             # 永久记忆文件
│   ├── identity/          # 你是谁
│   ├── artifact/          # 我们创造的东西
│   ├── topic/             # 话题索引（版本链）
│   └── memory/            # 通用记忆碎片
└── hooks/                 # 生命周期钩子脚本
```

**体量控制**：
- 原始对话保留 60 天，仅用于自进化对比
- 60 天后只保留语义摘要，原文删除
- 每条记忆平均 < 2KB，10 年对话预计 < 50MB
- bge-m3 嵌入模型（340MB），完全本地，无 API

### 5 层架构

```
┌─────────────────────────────────────────┐
│  5. Curator 层（规则驱动，主动管理）     │
│  矛盾检测 / 合并提醒 / 健康报告 / 立场过滤 │
├─────────────────────────────────────────┤
│  4. Evolution 层（LLM 驱动，被动+主动）  │
│  信任等级 / 版本链 / 反思报告             │
├─────────────────────────────────────────┤
│  3. Organization 层（记忆结构）           │
│  identity / topic(v版本链) / artifact /   │
│    memory(信任等级) / conversation(60天)  │
├─────────────────────────────────────────┤
│  2. Access 层（检索管道）                │
│  search → timeline → get（3层）         │
│  + 立场过滤器 + 时间窗                   │
├─────────────────────────────────────────┤
│  1. Storage 层（持久化）                 │
│  SQLite + FTS5 + sqlite-vec            │
│  WAL 模式 / HOT-WARM-COLD 分层          │
└─────────────────────────────────────────┘
```

### 记忆分类（4 类 + 1 动态）

| 类型 | 内容 | 存储方式 |
|------|------|---------|
| `identity` | 你是谁、目标、偏好、约束红线 | 语义摘要 + 向量 |
| `artifact` | 我们创造的所有东西（代码/文档/方案） | 语义摘要 + 关联 topic |
| `topic` | 话题索引，跨所有对话召回 | 向量 + FTS5 + 版本链 |
| `memory` | 通用记忆碎片 | 语义摘要 + topic 标签 + 信任等级 |
| `conversation` | 对话存档（临时的，60天后清除） | JSONL 原文 |

### 自进化机制

**阶段 1：被动积累（对话结束时自动）**
```
对话结束 → 钩子触发 → 提取新增事实 + 关键词 + 关联已有记忆 →
生成"待确认记忆" → 写入待审核区 → 用户下次对话时提示
```

**阶段 2：主动反思（积累 20 条或每周一次，用户批准后）**
```
系统分析待审核记忆 → 发现矛盾/重复/可合并 →
生成"反思报告"（中文）→ 展示给用户 → 用户批准 → 写入永久记忆
用户否决 → 标记为忽略 + 记录理由
```

**信任等级机制**：
- L1：新建，未验证 → 显示给用户但不自动注入
- L2：被再次验证 → 轻量注入
- L3：验证 3 次 → 自动注入，仅展示摘要

进化由「重复验证」驱动，不是「积累数量」驱动。

### 话题版本链

```
topic/ai-memory.md
  ├── v1 (2025-03): "AI记忆应该像图书馆"
  ├── v2 (2025-05): "AI记忆应该主动反思"
  └── current_ref: v2
```

每次讨论该 topic 产生新版本，自动建立引用链。检索时优先返回 current_ref，timeline 时可追溯演变。

### 向量检索管道（3 层）

```
用户输入
  ↓
1. search(query) → 返回 3-5 条语义最相似的记忆 ID（~50-100 tokens/result）
2. timeline(around_ids) → 补充这几条记忆附近的上下文（时间维度增强）
3. get(ids) → 取出完整内容注入上下文（仅对筛选后的 ID）
  ↓
节省 ~90% token
```

**立场过滤器**：检索结果重排时，淘汰与当前立场明显矛盾的旧记忆（保留「曾考虑过的方案」作为历史记录）。

### Curator 层（规则驱动）

纯规则，不依赖 LLM：
- 新记忆入库前：检查是否与已有记忆矛盾（字符串 overlap 检测）
- 每周：检测 topic 的 memories 超过 10 条未合并 → 提醒
- 每月：检测 identity 是否过时 → 提醒更新
- 每季度：生成「记忆健康报告」

### 生命周期钩子

```
SessionStart    → 注入 identity + 最近的 topic 相关记忆
UserPromptSubmit → 实时检测是否需要检索记忆（按需注入）
Stop             → 生成本次对话摘要，写入待审核区
SessionEnd       → 触发自我反思检查（积累量判断）
```

## Trade-offs

| 权衡 | 选择理由 |
|------|---------|
| sqlite-vec vs ChromaDB | sqlite-vec 无独立进程，体量小，Windows 兼容好；牺牲部分召回率换简洁 |
| bge-m3 嵌入模型 | 最小一档 embedding 模型（340MB），CPU 可跑，无 API 依赖 |
| 60 天原文清除 | 原文保留无上限；60 天足够对比，摘要才永久 |
| 信任等级 vs 直接覆盖 | 直接覆盖会丢失「观点演变」；信任等级保留历史轨迹 |
| 立场过滤器 | 可能过滤掉有价值的「旧观点」；解法：单独保留「历史争议」区 |

---

## Success Criteria

1. **安装后新对话立即可用**：读取 identity + 向量检索上次对话，无需用户手动配置
2. **每次对话结束自动沉淀**：新记忆进入待审核区，对话不丢失
3. **检索响应 < 500ms**：sqlite-vec 本地向量，embed-server 常驻 RAM
4. **10 年记忆 < 50MB**：只存摘要，向量压缩，原文 60 天后清除
5. **自进化可感知**：用户每月收到一次「记忆健康报告」，看到系统在工作
6. **零外部依赖**：pip install 后完全离线运行，无 API key，无云服务
7. **断电不丢**：WAL 模式，任何异常退出不影响已写入数据
